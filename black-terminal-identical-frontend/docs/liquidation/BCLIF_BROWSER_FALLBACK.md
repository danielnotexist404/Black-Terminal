# BCLIF Browser Fallback

The client priority is verified persistent tiles/live edge, browser-session fallback, then deterministic fixture in explicit local test mode only. It probes the protected persistent status before opening a Bybit browser socket. Persistent and browser models are never merged for the same range.

HTTP 401/403 is fail closed and cannot activate fallback. Authenticated `NOT_DEPLOYED`, a missing migration mapped to unavailable, or a genuine collector outage may activate fallback. If verified persistent history later becomes temporarily stale, the client retains it visibly as stale and retries rather than replacing it with a second historical authority.

The always-visible provenance label is not controlled by the diagnostics toggle:

```text
COLLECTOR: BROWSER SESSION
PERSISTENCE: OFF
HISTORY: BUILDS ONLY WHILE THIS CHART IS OPEN
```

Persistent mode reports the node ID, persistence `ON`, and continuous-history status. The deterministic fixture is synthetic, local/test-gated, and never trading data.
